🚀 Processo de inicialização da operação
PASSO 1

Abrir Docker Desktop.

PASSO 2

Localizar o container evolution-api.

PASSO 3

Clicar em PLAY. Não utilizamos docker compose via CMD no fluxo operacional.

PASSO 4

Validar localmente:

http://localhost:8080

Resposta esperada:

{
  "status": 200,
  "message": "Welcome to the Evolution API, it is working!"
}
PASSO 5

Abrir CMD e executar:

cd C:\cloudflared cloudflared.exe tunnel --config C:\cloudflared\config.yml run evolution

A janela deve permanecer aberta durante toda a operação. Não fechar.

PASSO 6

Validar Tunnel:

https://evolution.samuelvinsansi.com.br
PASSO 7

Abrir o CRM:

https://painel.samuelvinsansi.com.br
PASSO 8

Acessar Configurações → Chips WhatsApp e validar se os chips estão conectados.

✅ Checklist operacional
⚠ Regras importantes
  1. Não alterar a estrutura atual de Cloudflare Tunnel sem necessidade.
  2. Não alterar nomes de instância da Evolution sem atualizar o CRM.
  3. O CRM deve sempre utilizar a URL pública https://evolution.samuelvinsansi.com.br e nunca localhost.
  4. Antes de qualquer alteração estrutural, validar envio, recebimento, persistência no banco, conversas e caixa de entrada.
  5. Toda nova implementação deve preservar Evolution, Supabase, Webhook, Conversas e Caixa de Entrada.
🛑 Processo de encerramento
  1. Fechar a janela CMD do Cloudflare Tunnel.
  2. Parar o container evolution-api no Docker Desktop.
  3. Encerrar Docker Desktop se necessário.

Essa é a arquitetura oficial atual do projeto e deve ser considerada como ambiente padrão de produção.
