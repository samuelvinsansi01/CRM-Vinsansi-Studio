GET /api/whatsapp/conversation-commercial?conversationId=<ID>
Retorna:
- contractVersion
- conversationId
- linked
- leadId
- leadName
- alternativeName
- displayName
- leadStatusId
- stage
- editable
- allowedTransitions
- designDueDate
- designDueDateEditable
- updatedAt

POST /api/whatsapp/conversation-commercial

Alterar estágio:
{
  "action": "stage",
  "conversationId": 123,
  "stage": "aguardando_design"
}

Alterar/remover data do design:
{
  "action": "design_due_date",
  "conversationId": 123,
  "designDueDate": "2026-09-10"
}

Para remover a data:
{
  "action": "design_due_date",
  "conversationId": 123,
  "designDueDate": null
}

ESTÁGIOS CANÔNICOS R59

REGRAS
- O backend entrega allowedTransitions; clientes não precisam inventar o fluxo.
- set_lead_commercial_stage_r59 continua soberana para validar a transição no banco.
- Somente lead enviado (lead_status_id = 5) tem estágio comercial.
- Alteração exige leads.edit, mas não exige whatsapp.reply: editar Comercial não equivale a enviar mensagem.
- A data do design só é editável em aguardando_design.
- Uma nova data não pode ser gravada no passado.
- Data já planejada pode naturalmente se tornar atrasada e continua preservada.
- Mensagem recebida/enviada nunca altera estágio automaticamente.

UX NO CRM
- O Comercial aparece no cabeçalho/contexto da conversa.
- O estágio é alterado diretamente por select, sem abrir a tela do lead.
- Em Aguardando design, a data prevista é editada no mesmo contexto.
- Atualização acontece sem refresh visual da conversa.
